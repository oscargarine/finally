# 01-TOOLS

> Template generated by `harness` on 2026-10-06.

Operational arsenal for **FinAlly**. Each subdirectory is a **tool** that
combines (a) credentials co-located in its own `.env` and (b) the
scripts/CLIs that consume them.

> **Operations, not runtime.** The scripts here are the ones an operator
> runs from the terminal. The SDK that the app consumes in production
> **does not live here** — it lives in `backend/`.

## Conventions

- **Tool folder**: UPPERCASE with `_` separators — `OPENROUTER`, `MASSIVE`.
- **One folder = one external provider.**
- **Scripts**: snake_case, verb + object — `test_connection.sh`.
- **`.env` variables**: UPPERCASE with provider prefix.

| File | Required | Purpose |
|------|----------|---------|
| `.env` | yes (if secrets) | Real credentials — gitignored. |
| `.env.example` | yes | Public template with variable names and empty values. |
| `.gitignore` | yes | At least `.env` and `keys/`. |
| `README.md` | yes | What it does and how to run the scripts. |
| `CREDENTIALS.md` | yes | Detail of each variable, provider dashboard, rotation. |
| `test_connection.{py,sh}` | yes | Smoke-test, no parameters. |

Destructive actions require an explicit `--confirmar` flag; without it, dry-run.

## Adding a new tool

1. `cp -r 01-TOOLS/_TEMPLATE 01-TOOLS/<NAME>`
2. Fill in `.env.example` with the real variable names.
3. Create the real `.env` (gitignored).
4. **Implement `test_connection.{py,sh}` first.**
5. Update the tool's `README.md` and add a row to the catalog above.
